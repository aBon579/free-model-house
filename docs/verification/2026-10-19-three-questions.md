# 疑问 1：探测付费模型花钱吗？

## 答：**不花钱。**

### 实测证据

探测付费模型（`claude-haiku-4-5`）的完整响应：

```http
HTTP/1.1 401 Unauthorized
{"type":"error","error":{"type":"AuthError","message":"Missing API key."}}
```

**响应里没有任何 usage 字段**：

```
usage present: False
任何 usage/prompt_tokens 字段: []
```

### 为什么

上游在**凭据检查阶段**就拒绝了 —— 请求根本没进到推理。

```
请求 → 凭据检查 → ❌ "Bearer public 不适用于这个模型" → 401
                                    ↑
                          从没走到推理，所以没有 token 消耗
```

### 对比：探测**免费**模型会花钱

探测免费模型会真的走完推理，**消耗上游额度**。

所以探测的成本是**不对称的**：

| 探测对象 | 成本 |
|---|---|
| 付费模型（返回 401） | **零** —— 凭据检查就拒了 |
| 免费模型（返回 200/429） | **一次最小推理**（`max_tokens:16`，`content:"ping"`） |

### 所以策略是

**优先探"可能是付费"的** —— 零成本。
**免费模型的探测是可选的**（用户在管理台开），因为它花钱。

这正是我 `FreeVerifier` 的设计：

```go
// ⚠️ 探测"不是免费的"其实很便宜 —— 付费模型在凭据检查阶段就被拒了，
// 根本不会真的推理。真正消耗额度的是探"确实免费"的那些。
```

# 疑问 2：③ "上下文超限"是什么意思？

## 场景

你（或某个 agent）发了一个**很长的提示词**，比如 200K token。
模型最多只吃 150K。→ 上游拒绝。

```
400 Bad Request
{"error":{"message":"prompt is too long: exceeds context window"}}
```

## 关键问题：这时候该不该"换一个模型再试"？

**不该。** 换个模型也一样超 —— 除非那个模型窗口更大，
但那是"**候选过滤**"的职责（路由时按上下文长度挑模型），不是"**重试**"的职责。

## 我改了什么

| | 处理 | 结果 |
|---|---|---|
| **一种做法** | 400 + "context length" 落进 `CodeServer` → **可切换** | 会换模型重试 → 白白浪费一轮 |
| **我** | 加了 `contextRe` → 归到 `CodeClient` → **不可切换** | 直接把错误还给客户端 |

```go
case contextRe.MatchString(payload):
    // ⚠️ 上下文超限是**请求自己的错**。
    // 换个模型也一样超 —— 除非那个模型窗口更大，
    // 但那是"候选过滤"的职责，不是"重试"的职责。
    e.Code = CodeClient
```

## 与"上下文过滤"的区别

这是两件不同的事，容易混：

| | 机制 | 作用 |
|---|---|---|
| **上下文过滤** | 路由**之前** | 提示词 200K > 候选窗口 150K → **这个候选不选** |
| **上下文错误** | 上游**之后** | 已经发了，上游说超了 → **不再换模型** |

**过滤是预防，错误是事后。** 两者都要有。

# 疑问 3：④ "免费验证"是什么意思？

## 一句话

> **"免费"不是一个名字，是一个可以验证的事实。**
> 名字过滤是快速筛查，探测才是权威答案。

## 为什么要分两层

因为**名字会骗人**。我实测了三类情况：

| id | 名字像免费吗 | 实测结果 | 结论 |
|---|---|---|---|
| `minimax-m3.1-flash-free` | ✅ 像 | `403 IP 风控` | **免费** ✓ |
| `claude-haiku-4-5` | ❌ 不像 | `401 Missing API key` | **不免费** ✓ |
| `gpt-5` | ❌ 不像 | `401 Missing API key` | **不免费** ✓ |
| **`test`** | ❌ **不像** | `403 IP 风控` | **免费** ← 名字漏了！ |

**`test` 就是漏洞的证明** —— 它不含 "free"，但确实走免费路径。
纯名字过滤会漏掉它。

## 判定依据：上游的反应

```
401 "Missing API key"  →  确定【不是】免费车道
                          （Bearer public 只适用于免费车道）
200 / 429 / 403 闸门   →  在免费车道上
                          （429=限流，403=闸门或IP风控 —— 都说明凭据被接受了）
```

**为什么 401 是决定性的**：上游在查凭据时发现 `Bearer public` **不适用于这个模型**。
能走到 429/403 说明凭据**过了**检查。

## 两层机制

### 第一层：名字过滤（快，不保证）

```go
freeLaneRe = regexp.MustCompile(`(?:^|[-_])free(?:$|[-_.])`)
alwaysFree = {union-alpha, space-bunny-free, big-pickle}
```

**实测：85 个 id → 10 个（砍掉 88%）**

| 方向 | 风险 | 处理 |
|---|---|---|
| **漏**（`test` 这种） | **无害** —— 只是少几个选项 | 探测补上 |
| **多**（含 free 的付费 id） | **危险** —— 客户端会拿到必然失败的 id | ⚠️ 有专门断言防它 |

```go
if !IsFreeLane(row.ID) && strings.Contains(row.ID, "free") {
    t.Errorf("%q 含 'free' 但没被匹配 —— 规则有洞", row.ID)
}
```

### 第二层：运行时探测（慢，**权威**）

```go
v := NewFreeVerifier(lane.ProbeFree)
v.Verify(ctx, "claude-haiku-4-5")  // → not-free
v.Verify(ctx, "minimax-m3.1-flash-free")  // → free
```

**实测验证**（直播测试，全绿）：

```
minimax-m3.1-flash-free   → free
deepseek-v4.1-flash-free  → free
claude-haiku-4-5          → not-free
gpt-5                     → not-free
```

**"没探过"的一律保留** —— 探测有成本，
一个还没探过的模型不该被静默藏起来。

## 生产路径

```
拉全量 85 个
  ↓ ① 名字过滤（快，砍 88%）
~10 个候选
  ↓ ② 探测标注 free / not-free（用户可开，消耗额度）
not-free 的被剔除
  ↓
暴露给客户端的清单
```

⚠️ **第 ② 步默认关闭**（要花钱，虽然只花免费模型那份）。
所以在**没探测**时，保证是"名字过滤后的候选集"，不是"确证免费"。

**这一点我会在 UI 上说清楚** —— 不假装。

# 顺带：补完的两个缺口

## 缺口 1：`openref` —— 公开目录补容量

### 为什么需要

上游**不声明任何容量**（实测：85 行只有 `id/object/created/owned_by`）。
所以容量只能来自外部。两个来源**都不需要 key**：

| 来源 | 端点 | 实测 |
|---|---|---|
| `models.dev` | `https://models.dev/api.json` | 200，**opencode provider 下 128 个模型带容量** |
| `OpenRouter` | `https://openrouter.ai/api/v1/models` | 200，**18 个免费模型** |

### 实测覆盖度

```
实时免费清单 10 个，其中 9 个在 models.dev 里有容量
```

### ⚠️ 但发现了一个冲突

`deepseek-v4.1-flash-free`：

| 来源 | 上下文窗口 | 输出上限 |
|---|---|---|
| 我的规则表 | 1,048,576 | 262,144 |
| **models.dev** | **200,000** | **32,000** |

**差 5 倍。** 这就是**信任序**要解决的问题。

### 信任序（我加的约束）

```
实测 (probe)  >  上游声明 (opencode 自己的清单)  >  第三方目录 (models.dev)  >  本地规则表
```

而 opencode 的清单**不声明容量**，所以第三方目录**比实测低、比本地表高**。

### ⚠️ 一个关键的克制

**第三方目录的模态结论（能不能看图）不写进模型。**

因为模态是**路由硬过滤**的依据 —— 用猜出来的结论去过滤会误杀模型。
模态只能来自实测。

```go
// ⚠️ **模态结论只有实测来源才生效**。
if meta.HasModality && meta.Source == CapabilitySourceProbe {
    info.Vision = meta.Vision
    ...
}
```

容量则可以直接用 —— 它只影响软过滤，猜错的代价远小于误杀。

### 冲突埋掉，不猜

两个目录对同一个归一化 id 给出不同容量 → **那是"同名不同模型"**。
**宁可留空，也不要挑一个赢家** —— 挑错了会让一个模型带着别人的容量进路由。

```go
if existing.ContextWindow != v.ContextWindow || existing.MaxOutput != v.MaxOutput {
    delete(out, k)      // 埋掉
    conflicts[k] = true
}
```

## 缺口 2：清单信封兼容

原来的解析只认 `{"data":[...]}`。现在接受**所有见过的形状**：

```go
{"data":[...]} / {"models":[...]} / {"items":[...]}
[...（裸数组）]
行可以是对象（取 id）或字符串
```

**理由**：上游改一次响应格式，解析就该崩一次。
健壮的解析器接受所有形状，而不是赌一种。

## 顺带发现的两个 bug（测试抓到的）

| bug | 症状 | 修法 |
|---|---|---|
| 归一化**顺序**错了 | `deepseek_v4_flash_free` → `deepseek-v4-flash-free`（没剥掉后缀） | 先统一分隔符，**再**剥后缀 |
| `openrouter/auto` 被当成免费 | 它其实是**按路由到的模型计费**（pricing = -1） | 只有 `openrouter/free` 是 0/0 |
| OpenRouter `reasoning` 字段是**对象**不是布尔 | 解析直接崩 | RawMessage + 两种形状都吃 |

**最后一个还挖出了有价值的信息**：

```json
{"mandatory": true, "supported_efforts": ["max","xhigh","high","medium","low"], "default_effort": "max"}
```

`mandatory: true` = **思考关不掉** → 它的输出预算要加倍
（思考与可见答案共享同一个上限）。
这个我记进 `CanDisable` 了。
