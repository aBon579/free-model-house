# UI 设计方案

> FMH 的 Web 管理界面。定位是**"家里的配电箱"** —— 冷静、可靠、一眼看清状态。
> 它常驻在 NAS 上，可能一直开着，所以**没有装饰性光效**。

---

## 1. FMH 的界面要解决什么

FMH 是**NAS 设备** —— 用户可能是：

- 在**另一台电脑**上用 Claude Code，希望改个配置
- 在**手机**上想看一眼"今天用了多少"
- 家里其他人想**自己拿一把 key** 接进去

所以 FMH 的界面有一条**自己的主线**：

> **"让局域网里的人 30 秒内接上"** 是第一优先，
> 深度配置能力是第二优先。

这决定了页面的**排序**和**首屏内容**。

## 2. 信息架构

```
┌─ 侧边栏（240px，手机上收成抽屉）────────────────┐
│                                                  │
│  ◆ Free Model House          [本机]              │
│                                                  │
│  接入                                            │
│   ⌁ 快速接入        ← 首屏就是它                 │
│                                                  │
│  运行                                            │
│   ▦ 模型清单                                    │
│   ◔ 用量                                         │
│   ⚙ 上游源                                       │
│                                                  │
│  系统                                            │
│   ⚒ 服务设置                                     │
│                                                  │
│  ─────────────────────────────                  │
│  ● 在线 · v0.1.0              [退出]             │
└──────────────────────────────────────────────────┘
```

**5 个页面**：

| 页面 | 做什么 |
|---|---|---|
| **快速接入** | **首屏**。给出 base URL、LAN Key、各 Agent 的配置片段，一键复制 | 放在第一位 —— 因为 NAS 场景下，**装完之后第一件事就是接入** |
| **模型清单** | 搜索/筛选/复制 ID/单模型体检/启停 | 基本一致，但**多一列"实际服务"**（见 §4.2） |
| **用量** | token 曲线、按模型明细、失败与恢复 | 一致 |
| **上游源** | 三条车道的配置、凭据（只显示指纹）、刷新、探测 | 只有 3 条车道，所以**这个页面可以做得很轻** |
| **服务设置** | LAN 开关/端口、路由策略、冷却参数、探测、档位 | 一致 |

**砍掉的**（FMH v1.0 不做，且**不假装有**）：
EAC 协付、13 个账号渠道、公告系统、自动升级、多出口代理池、赞助商广告页。

## 3. 视觉语言

### 3.1 定位

**"家里的配电箱"** —— 冷静、可靠、一眼看清状态。

它要常驻在 NAS 上，可能一直开着，所以**不该有装饰性光效**。

### 3.2 色板

亮色主题是**暖米**色调 —— 像暖白纸，不是纯白（纯白长时间盯着看很"硬"），
但**不能太黄**（太黄会变成泛黄的老照片）。

```css
/* ── 亮色（默认）──────────────────────────────── */
--bg:        #faf7f2;   /* 页面底色 —— 暖米白 */
--surface:   #fffdf9;   /* 卡片 */
--surface-2: #f4efe6;   /* 次级面板 */
--sidebar:   #e8e1d1;   /* 侧栏 —— 比内容区暗，"沉下去" */
--line:      #e6dfd2;
--line-soft: #f0eade;

--ink:       #1c1917;
--ink-2:     #443c33;
--ink-3:     #6b5f52;

/* 强调色：琥珀（跟暖色底呼应） */
--accent:      #b45309;
--accent-2:    #d97706;
--accent-ink:  #ffffff;
--accent-soft: #fdf2e3;
--accent-line: #f0d5ab;

/* 状态色 */
--ok:    #047857;    --ok-soft:    #e8f6f0;
--warn:  #a16207;
```

暗色主题是**深蓝黑**，侧栏再深一档（近黑），内容区更亮 —— 浮在上面。

```css
/* ── 暗色 ─────────────────────────────────────── */
--bg:        #0b1220;
--surface:   #111a2e;
--surface-2: #1a2438;
--sidebar:   #010306;
--line:      #24304a;

--ink:       #e8eef9;
--ink-2:     #94a3b8;
--ink-3:     #64748b;

--accent:      #38bdf8;
--accent-2:    #7dd3fc;
```

**侧栏跟内容区的边界**靠三样东西一起：

| 手段 | 亮色 | 暗色 |
|---|---|---|
| 底色深浅差 | 侧栏比内容区暗 | 侧栏比内容区**更深**（近黑） |
| 右边一条实线 | `#d0c3ab` | `#1e2a3f` |
| 侧栏投影 | 极淡 | 更明显（深色下"1px 边线"太弱） |

### 3.3 形状与阴影

```css
--r-sm: 6px;   /* 输入框、徽章 */
--r-md: 10px;  /* 卡片 */
--r-lg: 14px;  /* 弹窗 */

--shadow-1: 0 1px 2px rgba(15, 23, 42, 0.05);
--shadow-2: 0 4px 16px -4px rgba(15, 23, 42, 0.10);
--shadow-3: 0 16px 40px -12px rgba(15, 23, 42, 0.18);
```

### 3.4 字体

```css
--font: ui-sans-serif, system-ui, -apple-system, 'Segoe UI',
        'PingFang SC', 'Microsoft YaHei', sans-serif;
--mono: ui-monospace, 'SF Mono', 'Cascadia Code', Consolas, monospace;
```

模型 ID、Key、token 数一律用 `mono` —— 它们要**能逐字符比对**。

### 3.5 动效

**克制到几乎没有。**

- 按钮 hover：底色变亮一档（`--surface-hover`）
- 按下：轻微缩放 + 光晕
- 指示灯：1.6 秒呼吸

**没有**渐变、没有位移入场、没有光斑漂移 —— 它不是消费级产品。

## 4. FMH 独有的两个 UI 概念

FMH 真正需要的东西：

### 4.1 车道徽章（Lane Badge）

模型来自两个性质完全不同的源，用户必须一眼看出区别：

```
┌────────────────────────────────────────────────┐
│  ● Zen 免密车道                                  │
│    不需要任何凭据 · 全局共享配额 · 可能被限流      │
│                                                 │
│  ● OpenRouter 免费模型                           │
│    用你自己的 OR Key · 每日额度有限 · 稳定些      │
└────────────────────────────────────────────────┘
```

模型清单里每个模型带一个车道徽章：

```
deepseek-v4.1-flash-free          [免密]  ✓ 可用   1.8s
deepseek/deepseek-r1:free         [OR]    ✓ 可用   2.4s
```

**免密徽章用紫，OR 徽章用青** —— 与 `--lane-zen` / `--lane-openrouter` 对应。

### 4.2 "实际服务"列

这是 FMH 最重要的一个 UI 元素，直接来自故障转移机制：

```
┌────────────────────────────────────────────────────────────┐
│ 请求的模型            实际服务的模型         状态          │
├────────────────────────────────────────────────────────────┤
│ deepseek-v4.1-flash    deepseek-v4.1-flash    ✓             │
│ deepseek-v4.1-flash    glm-5.3-flash         ⚠ 已切换       │
│ union-alpha            union-alpha            ✓             │
└────────────────────────────────────────────────────────────┘
```

**为什么必须有**：故障转移是**静默**的。用户请求 A 得到了 B 的回答，
如果没有这一列，他会以为"这个模型今天变笨了"。
这一列 + 请求头 `X-FMH-Model` 一起，把"为什么得到这个答案"变成可解释的。

**它怎么来的**：每个请求的 `actual_model` 记进用量表，
模型清单页按"最近一次实际服务的模型"聚合显示。

### 4.3 快速接入页（首屏）

这是 FMH 的**门面**。

```
┌──────────────────────────────────────────────────────────────┐
│  快速接入                                                     │
│  把免费模型接进你的 Agent，只需要两步                          │
│                                                              │
│  ① 局域网地址与密钥                                           │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ Base URL                            [复制]             │  │
│  │ http://192.168.31.5:8678/v1                           │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 局域网 Key  [免额度]                                    │  │
│  │ fmh-3f9a2b8c…                      [显示完整 Key] [复制] │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ② 选一个你的工具                                             │
│  ┌──────────┬──────────┬──────────┬──────────┐              │
│  │ Claude   │ OpenCode │  Cline   │   Aider  │              │
│  │   Code   │          │          │          │              │
│  └──────────┴──────────┴──────────┴──────────┘              │
│                                                              │
│  展开任一项 →                                                  │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ # Claude Code                                           │  │
│  │ export ANTHROPIC_BASE_URL=http://192.168.31.5:8678/v1 │  │
│  │ export ANTHROPIC_AUTH_TOKEN=fmh-3f9a2b8c…              │  │
│  │                                          [复制这段]     │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

⚠️ **Key 默认打码**，要显式点「显示完整 Key」才出明文 ——
   避免投屏时泄露。旁边那句「别截图」是提醒。

⚠️ **Base URL 用浏览器的实际地址**算的，不是写死的 `localhost` ——
   用户是通过 NAS-IP 访问的，写死就错了。

⚠️ **Claude Code 的 `ANTHROPIC_BASE_URL` 带 `/v1`** ——
   Claude Code 自己会拼 `/v1/messages`。

**关键交互**：
- **LAN 关闭时**，这个页面显示一个**显眼的横幅**而不是让人去猜
- **Key 默认打码**，点"显示"才明文（避免投屏/截图泄露）
- **每个工具一个 tab**，切 tab 不重新请求
- 一键复制的是**完整的可执行片段**，不是让人自己拼

⚠️ **「显示完整 Key」的实现要点**（踩过坑）：

显示完整 Key 要**重新请求后端**（`/api/keys?reveal=1`）——
明文不留在普通接口的响应里。所以：

1. **显示状态由页面持有**，不能只存在 `CopyField` 组件内部 ——
   组件不知道"要重新请求"这件事。
   → `CopyField` 有了**受控模式**（传 `revealed` 就以外部为准）。
2. **受控模式下组件不能再打码** ——
   否则页面拿到的明文又被 `maskMiddle()` 打回指纹，
   表现就是「点了显示，界面没变」。

⚠️ 这个坑的表现极具迷惑性：**网络请求发了、200、响应体里有完整 Key，
但 DOM 里还是指纹**。因为 `maskMiddle(完整Key)` 和指纹**长得一模一样**
（都是首 8 + 末 4 位）。

「服务设置」页有**两个独立的开关**（本机 Key / 局域网 Key），
互不影响 —— 隐藏其中一个，另一个保持原状。

### 6.2.3 模型状态分类

⚠️ **文案原则** —— 好处是"状态 = 该做什么"：

| 状态 | 显示 | 含义 | 该做什么 |
|---|---|---|---|
| `available` | 可用 | 探测通过 | 直接用 |
| `unknown` | 未探测 | 没探过，或结论过期 | 探一下才知道 |
| `throttled` | 暂时限流·可重试 | 被限流 | 等一会就好，路由会自动换模型 |
| `region-blocked` | 地区受限 | 出口所在地区被屏蔽 | 换出口才有用 |
| `abuse-blocked` | 出口被风控 | 上游认为这个 IP 在滥用 | 整条车道不可用，换出口 |
| `unavailable` | 不可用 | 上游明确拒绝 | 别试了 |

⚠️ **"限流"改成"暂时限流·可重试"** —— 原来的"限流"会让人以为模型坏了，
   而它其实是**暂时的**。

⚠️ **"区域限制"改成"地区受限"** —— 更口语。

⚠️ **"IP 风控"改成"出口被风控"** —— 重点是"**出口**"，
   因为用户该做的是换出口，不是换模型。

⚠️ **六个状态要全列在筛选栏里** —— 之前只列了 4 个，
   于是"地区受限"和"出口被风控"这两种状态的模型**筛不出来**。

⚠️ **排序**按 `STATE_ORDER`：
   可用 < 未探测 < 限流 < 地区受限 < 不可用
   —— 限流在"地区受限"**前面**，因为限流是**暂时**的，
   而地区受限在这次会话里基本没救。

#### 出口信息

⚠️ **面板必须显示"我现在从哪个 IP 出去"** ——

免密车道的可用性是**网络路径的属性**。上游的原话是
"detected abusive traffic from **this IP address**"。

不显示出口的话，用户看到"出口被风控"这个红字，
**不知道该换什么** —— 换模型？换代理？换 VPN？

「上游源」页有两条横幅：

| 情况 | 显示 |
|---|---|
| 正常 | 「当前出口 203.0.113.42（CN）」+ 一句解释（跟着出口走） |
| 整条车道被锁 | 红色横幅：「整条免密车道被锁」+ 理由 + "N / M 个模型被同一理由拒绝" + "换出口才有用" |

⚠️ **"整条车道被锁"比逐个标红更有用** ——
   因为真正要换的是出口，不是模型。逐个标红会误导用户去逐个换模型。

## 5. 页面细则

### 5.1 模型清单

```
┌──────────────────────────────────────────────────────────────────┐
│ [🔍 搜索模型 ID 或名称]  [车道: 全部▾] [能力: 全部▾] [状态▾]      │
│                                          [刷新清单] [探测全部]    │
├──────────────────────────────────────────────────────────────────┤
│ 模型 ID                    车道   能力      状态    首字   实际服务│
├──────────────────────────────────────────────────────────────────┤
│ deepseek-v4.1-flash-free  [免密] 图✓ 思✓   可用   1.8s  —       │
│ glm-5.3-flash-free        [免密] 图✓ 思✓   可用   2.1s  —       │
│ deepseek/deepseek-r1:free [OR]   思✓     可用   2.4s  —       │
│ muse-spark-1.3            [免密] 图✓ 思✓   限流   —     —       │
│ longcat-2.5-preview-free  [免密]  —       未知   —     —       │
└──────────────────────────────────────────────────────────────────┘
```

**关键设计**：
- **虚拟滚动**（TanStack Virtual）—— 50+ 模型必须流畅
- **能力徽章带来源标记**：实测过的显示实心，未实测的显示虚线/浅色
  （对应 `capability_source` 字段，让用户知道这个结论有多可靠）
- **限流行显示冷却倒计时**（不是只显示"限流"）
- **"实际服务"列**显示最近一次实际服务的模型
- 行尾的操作：复制 ID / 单模型体检 / 启停

### 5.2 上游源

```
┌──────────────────────────────────────────────────┐
│  ● OpenCode Zen 免密车道          [已启用 ✓]      │
│    状态: 正常 · 上次刷新 2 分钟前 · 88 个模型      │
│    凭据: 无需凭据（共享凭据）                       │
│    [刷新清单] [重新探测]                            │
├──────────────────────────────────────────────────┤
│  ● OpenRouter 免费模型            [已启用 ]      │
│    状态: 未配置 API Key                             │
│    凭据: [••••••••••••abcd]  [修改] [清除]        │
│    模型: 27 个免费模型                              │
│    [刷新清单] [重新探测]                            │
├──────────────────────────────────────────────────┤
│  ⚠ 自动跨模型调用（模型失败时自动换一个）      │
│    [关闭]  关闭时不消耗你的 OpenRouter 额度          │
└──────────────────────────────────────────────────┘
```

**凭据框的设计要点**：
- **只显示指纹**（`…abcd`），永不回显全文
- 保存时**空值 = 保持原样**（key 不在浏览器里往返）
- 有明确的风险提示

### 5.3 用量

```
┌────────────────────────────────────────────────────────┐
│  Token 用量                          [7天][14天][30天] │
│  ▁▂▃▅▇▅▃▂  1.2M                                     │
├────────────────────────────────────────────────────────┤
│  模型                 请求  回合  输入     输出    失败  │
│  deepseek-v4.1-flash   342   298  820K    190K     2   │
│  glm-5.3-flash         118    96  240K     45K     0   │
└────────────────────────────────────────────────────────┘
```

**"请求" vs "回合"必须分开显示**：
请求 = 物理上游请求数（含故障转移和续写），回合 = 用户实际发起的轮次。
两者分开，用户才能看懂"我发了 96 轮，为什么计了 118 个请求"。

### 5.4 服务设置

分组：**接入** / **路由** / **限流** / **探测** / **输出**

每个设置项：
- 标签 + 一句话说明（说明写"为什么"，不写"是什么"）
- 控件
- **有风险的项加一句后果说明**

例：
```
自动跨模型调用
  免费车道耗尽时，是否用你的 OpenRouter 额度兜底
  ⚠ 开启后会在你的 OpenRouter 账户上产生用量
  [关闭]
```

**未保存提示**：
离开页面有未保存改动时确认；后台轮询**不覆盖**用户正在编辑的草稿
（这个坑踩过 —— `settings.tsx` 里专门处理过）。

### 5.5 品牌标识

| 位置 | 用什么 | 尺寸 |
|---|---|---|
| 登录页 | `BrandMark size="md"` | 32×32 |
| 侧边栏 | `BrandMark size="sm"` | 28×28 |
| 浏览器标签页 | `favicon.svg`（+ `favicon.ico` 兜底） | 任意 |
| iOS 主屏 | `apple-touch-icon.png` | 180×180 |

⚠️ **logo 是图片资源，不是 CSS 画的** —— 所以集中在 `web/public/`，
   由 `tools/make-logo.py` 从根目录的 `logo.png` 生成。

⚠️ **源图不能直接当 favicon**：
   源图 1254×1254、**1.2 MB**、**没有透明通道**、**满图无留白**。
   直接用会让标签页加载 1.2 MB，而且方角在深色侧边栏上很生硬。
   所以生成脚本会：缩到 256 → **加圆角** → 导出 png / svg / ico。

⚠️ **logo 本身是深色的**（近黑底 `rgb(2,6,17)` + 亮蓝图形 `rgb(117,219,253)`）——
   亮色和暗色主题下都清晰，所以 UI 里**不需要**额外垫底色。

改了 logo 之后重新生成：

```bash
python3 tools/make-logo.py
cd web && npm run build
```

**UI 组件集要自己写**，不引 shadcn/ui 组件库（那是 Radix + CVA 的重依赖，
而且会带来自带的一套风格）。只用：
- `lucide-react`（图标）
- `@tanstack/react-query`（数据）
- `@tanstack/react-virtual`（虚拟滚动）
- `clsx` + `tailwind-merge`（class 合并）

### 6.2 状态管理

**不引入 Redux/Zustand**。那种
"把 API 调用抽到 .mjs 文件"的做法在 React 里是反模式 ——
TanStack Query 直接在组件里管数据缓存、重试、失效刷新。

**全局状态只有两样**：
1. 当前页面（hash 路由）
2. 主题偏好（`system` / `light` / `dark`，写 localStorage）

其余全是服务端状态，交给 Query。

### 6.2.1 主题：三档，不是两档

| 档位 | 行为 |
|---|---|
| `system` | 跟随操作系统（**默认**） |
| `light` | 强制亮色 |
| `dark` | 强制暗色 |

侧边栏的按钮**循环切换**这三档。

⚠️ **存的是"偏好"不是"解析结果"** ——
   如果存的是解析后的 `dark`，那么下次访问会变成"固定暗色"，
   系统主题再变就再也不跟了。

⚠️ **必须监听 `matchMedia` 的 `change` 事件** ——
   只在首次访问时读一次 `prefers-color-scheme` 是不够的：
   用户在系统设置里切换深色模式时，已经打开的页面应该跟着变。

⚠️ **侧边栏要跟随主题** ——
   之前侧栏写死成深靛色（`--sidebar: #0f172a`），切到亮色主题时它纹丝不动，
   看起来就像"主题没生效"。现在侧栏有一组**跟着主题走**的令牌：

```css
--sidebar          /* 侧栏底色 */
--sidebar-line     /* 分隔线 */
--sidebar-hover    /* 悬停底色 */
--sidebar-active   /* 选中底色 */
--on-sidebar       /* 文字 */
--on-sidebar-dim   /* 次要文字 */
--on-sidebar-active/* 选中文字 */
```

⚠️ **不要在侧栏里用 `bg-white/10` 这种硬编码** ——
   它假设侧栏永远是深色。亮色主题下会变成"灰底"。

### 6.2.2 复制：必须兼容 HTTP

⚠️ **`navigator.clipboard` 在非安全上下文里不存在** ——
   它只在 HTTPS 或 localhost 可用。而 FMH 是局域网服务，
   用户访问的是 `http://192.168.x.x:8678` —— **HTTP**。
   于是 `navigator.clipboard.writeText` 抛异常，
   而 `catch` 里什么都不做 —— 表现就是**"点了复制，一点反应都没有"**。

所以统一走 `web/src/lib/clipboard.ts` 的 `copyToClipboard()`：

1. 有 `navigator.clipboard` → 用它（HTTPS / localhost）
2. 没有 → 降级到 `document.execCommand('copy')` ——
   把文本塞进**离屏 textarea** → 全选 → 执行 copy。

⚠️ textarea 不能用 `display:none` ——
   某些浏览器对不可见元素拒绝复制。用 `position:fixed` + `opacity:0` + `z-index:-1`。

⚠️ 复制**失败要有反馈** —— 按钮变成红色 ✕ 并提示"复制失败，请手动选中复制"。
   静默失败比报错更让人困惑。

### 6.3 响应式

⚠️ **一个页面，不是两套**。

手机和电脑打开的是**同一个 URL**、**同一份 bundle**、**同一个 `index.html`**。
差别只在**布局怎么排** —— 全靠 CSS 媒体查询。

**没有** `navigator.userAgent` 判断，
**没有** `/m` 之类的移动端路由，
**没有**两套构建产物。

> 客户端（Claude Code / OpenCode / Cline）跑在终端里，不是浏览器。
> 管理台是用户**偶尔**看一眼 NAS 状态用的。
> 所以移动端是"锦上添花"，不是主力场景 —— 但**保留**，不做成另一套页面。

| 断点 | 行为 |
|---|---|
| ≥ 1024px | 侧栏常驻 240px；模型清单是 7 列表格 |
| < 1024px | 侧栏收进抽屉（顶栏汉堡）；模型清单变卡片列表 |

#### 侧栏可收起（桌面端）

桌面端侧栏能收成 **58px 的一列图标** —— 这样宽屏下内容区能多出 182px。

| | 展开 | 收起 |
|---|---|---|
| 宽度 | 240px | 58px |
| 导航项 | 图标 + 文字 | **只有图标**（靠 `title` 提示） |
| 分组标题 | 显示 | 隐藏（留 16px 间距占位） |
| 品牌区 | logo + 名字 + 版本徽章 | 只有 logo |
| 状态行 | 在线 + 模型数 | 隐藏 |
| 收起按钮 | 「收起」 | 「展开」图标 |

⚠️ 收起状态**持久化**在 `localStorage['fmh-sidebar-collapsed']`。

⚠️ **默认展开** —— 侧栏是主要导航，一进来只剩一列图标的话，
   新用户不知道能点哪儿。

⚠️ 收起后**必须留 `title`** —— 光有图标认不出是什么。

#### 局域网推理：三个档位

⚠️ 之前只有一个 `lan_enabled` 布尔开关 —— 粒度太粗：
要么全开（谁都��能用你的免费额度），要么全关。

现在三档：

| 档位 | 行为 |
|---|---|
| `off` | 局域网里的 Agent 完全用不了（LAN Key → 403） |
| `limited` | 局域网可用，但**限流 + 限并发**（超了 → 429 + `Retry-After`） |
| `lan` | 局域网可用，不限量 |

⚠️ **限流只对 LAN Key 生效** —— 本机 Key（管理台自己）不受限，
   否则管理台自己的轮询会被自己的限流打掉。

⚠️ **限额是对整个网关生效的，不是对单个 Key** ——
   免密车道的配额是**全局共享**的，
   限制单个 Key 等于没限制（多拿几把 Key 就绕过了）。

⚠️ **超限返回 429 而不是 403** —— 客户端看到 429 会退避重试，
   看到 403 会直接放弃。

⚠️ 切到「限量」档时，如果限额是 0（= 不限），
   要给个**能用的默认值**（30 次/分钟、4 并发）——
   否则档位名写着"限量"但实际不限量。

#### 触点尺寸

⚠️ 桌面端的 28px 小按钮是**故意**的 —— 它让表格更紧凑，一屏能看更多模型。

但在手机上 28px **点不准**（Apple 建议 44px，Android 建议 48px）。

所以用 `@media (pointer: coarse)` 区分 —— "主指针是粗的" = 触屏设备：

```css
@media (pointer: coarse) {
  .fmh-touchable      { min-height: 36px; }   /* 小按钮放大 */
  .fmh-touchable-icon { min-width: 40px; min-height: 40px; }  /* 图标按钮 */
}
```

⚠️ **桌面端一点不改** —— 媒体查询不匹配。

#### 开关的热区

⚠️ 开关视觉上只有 22px 高，但它的**可点区域**要够。

用伪元素把热区撑开，**视觉完全不变**：

```css
@media (pointer: coarse) {
  .fmh-switch::before { content: ''; position: absolute; inset: -9px -1px; }
}
```

实测（375px 视口，`pointer: coarse`）：
- 视觉盒子仍是 38×22
- 偏上 8px 点击 → **仍然命中**（`aria-checked` 从 `true` 变 `false`）
- 偏上 9px → 命中开关；偏下 9px → 命中下一个元素（正好是热区边界）

⚠️ **滑块必须显式给 `left-0`** ——
   绝对定位元素没有 `left` 时会退回**静态位置**，
   而按钮的静态位置是内容流末尾 —— 于是滑块跑到轨道外面，
   `translate-x-[18px]` 只是把它推得更远。

尺寸：轨道 38px、滑块 18px、左右各留 2px →
关闭时 `left=2`，开启时 `left=18`（38-18-2）。

实测：滑块 `x=2`（关）/ `x=18`（开），右余 `18`/`2` —— 都在轨道内。

#### 安全区（刘海屏 / 底部横条）

不处理的话：顶部标题被刘海盖住，底部按钮滑到 Home 指示条底下点不中。

```css
:root {
  --safe-top:    env(safe-area-inset-top, 0px);
  --safe-bottom: env(safe-area-inset-bottom, 0px);
  --safe-left:   env(safe-area-inset-left, 0px);
  --safe-right:  env(safe-area-inset-right, 0px);
}
```

三个应用点：
- `.fmh-topbar` — 顶部避开刘海
- `.fmh-sidebar` — 抽屉顶部避开刘海、底部避开 Home 条
- `.fmh-content` — 内容底部避开 Home 条

`env()` 在没有这些区域的设备上返回 0，所以**可以无条件用**。

### 6.4 无障碍

- 所有交互元素有 `aria-label`
- 焦点可见（`outline: 2px solid var(--accent)`）
- 状态不只用颜色表达（限流行同时有图标 + 文字）
- 表格用真 `<table>` + `scope`（读屏可用），虚拟滚动用 `aria-rowcount`
- 尊重 `prefers-reduced-motion`

## 7. 界面之外的两个非 UI 设计决定

这两个决定了 UI 能不能"诚实"：

**① 读取状态不发推理请求。**
面板的 15 秒轮询、刷新清单、看用量 —— **一个 token 都不花**。
只有"单模型体检"和"主动探测"才发请求，而且按钮上要写明"会消耗上游额度"。

**② 上游凭据永不回显。**
管理台输入框只显示指纹。保存时空值 = 保持原样（key 不在浏览器里往返）。
导出配置时凭据被替换成 `‹已隐去›`，除非显式请求 `?secrets=1`。

（这两条都不是 UI 层的选择，是**安全模型**的必然结果。
UI 只是把它如实呈现出来。）
